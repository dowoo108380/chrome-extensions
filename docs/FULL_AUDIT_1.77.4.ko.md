# Browser Toolbox 1.77.4 전체 점검

검사일: 2026-09-29 · Windows 11 · Chrome 154.0.8037.58

## 여백 재발의 원인

이전 수정은 불일치를 감지해 폭 확장을 되돌렸지만, YouTube가 영상과 조작부의 크기를 다시 계산하도록 하는 연결이 부족했습니다. 사용자가 제시한 문구는 이 복구 경로가 실행된 결과였습니다. 기존 시험도 창의 `resize` 신호로만 내부 크기를 갱신하는 플레이어를 충분히 재현하지 못했습니다.

실제 문제가 있는 탭에서 저장된 실패 측정값을 확인했습니다. 아래 수치는 화면 캡처의 이미지 픽셀이 아닌 CSS 픽셀입니다.

| 요소 | 확장 전 | 실패 당시 |
|---|---:|---:|
| 플레이어 바깥 상자 | 1840 × 1035 | 2308.8 × 1298.7 |
| 실제 video 요소 | 1840 × 1035 | 1840 × 1035 |
| 진행 막대 너비 | 1816 | 1816 |
| 버튼 줄 너비 | 1816 | 1816 |

바깥 상자만 넓어지고 YouTube가 관리하는 영상·조작부는 이전 크기에 남았습니다. 별도 실제 YouTube 시험 탭에서 같은 불일치를 만든 뒤 일반 DOM `resize` 알림을 한 번 전달하자 영상은 2309px, 진행 막대는 2285px로 함께 갱신됐습니다. 시험용 바깥 스타일은 복원했고 해당 탭은 닫았습니다. 사용자의 원래 탭은 새로 고치거나 다른 영상으로 이동하지 않았습니다.

1.77.4는 안정된 크기 불일치를 관측한 경우에만 제한적으로 크기 변경을 알립니다. 같은 플레이어·크기·준비 상태에는 알림을 반복하지 않습니다. 다음 렌더링 프레임에서 영상, 진행 막대, 버튼 줄의 실제 크기를 다시 확인합니다. 알림을 보냈다는 사실을 성공으로 보고하지 않습니다. 영상이나 진행 막대의 너비를 직접 강제하거나 YouTube 비공개 크기 API를 호출하지 않습니다.

영상 메타데이터가 늦게 준비되는 동안에는 실패 판정 시간을 소모하지 않습니다. 다음 영상으로 바뀌면 새 영상의 크기를 다시 확인하고, 기능 해제 시 원래 폭으로 줄어든 사실도 YouTube에 알려 이전 크기의 영상·탐색 좌표가 남지 않도록 했습니다. 실제로 갱신되지 않는 플레이어에 대한 원상 복원 검사는 유지했습니다.

측정 기록: [live-observations.json](verification/full-audit-1.77.4/live-observations.json).

중복된 너비 상태 초기화를 공통 함수로 정리했고, 세션 이전보다 먼저 실행되던 잘못된 삭제를 제거했습니다. 기본 미디어 동작, 원본 플레이어 스타일, 기존 사용자 설정과 과거 검증 기록은 보존했습니다. 새 권한이나 실행 의존성은 추가하지 않았습니다.

## `null` 두 종류의 구분

저장소의 숫자·화질 설정이 `null`인 경우는 이번에 오류를 재현하고 수정했습니다. 설정을 읽는 API 자체가 실패한 경우에는 저장 성공이나 정상 기본값으로 가장하지 않고 오류를 표시합니다.

YouTube 톱니바퀴의 `aria-label` 또는 `data-tooltip-title`에 문자열 `"null"`이 들어간 현상은 별개입니다. 이번 실제 페이지에서는 `설정`으로 보였고 같은 현상을 재현하지 못했습니다. 프로젝트 코드에는 네이티브 톱니바퀴의 두 속성에 값을 쓰는 코드가 없었습니다. 따라서 그 문자열을 만든 원인을 특정 확장이나 YouTube로 단정하지 않습니다. 설명이 `"null"`이어도 실제 톱니바퀴와 화질 메뉴를 찾는 기존 대응은 유지했고, 시험 중 원본 접근성 속성을 임의로 바꾸지 않는 것도 확인했습니다.

## 검증 방식과 증거

수정 전 1.77.3은 기존 Node 83개와 브라우저 30개 묶음을 모두 통과했습니다. 따라서 기존 시험의 통과만으로 이번 실제 증상을 해결했다고 판단하지 않았습니다.

새 회귀 검사 12개를 같은 수정 전 코드에 적용했습니다. 11개가 실패하고 원래 이미지 속성 복원의 대조 사례 1개가 통과했습니다. 수정 전 파일은 `.test_results/audit-1.77.3-baseline`에 보존했습니다. 페이지 이탈 시점은 마우스 이벤트 처리가 끝난 뒤, 선택기의 두 번째 화면 갱신 전으로 고정하여 검사합니다.

확장 설치 검사에서는 임시 Chrome 프로필에 실제 MV3 확장을 로드합니다. 저장소·콘텐츠 스크립트의 격리 환경·페이지의 크기 계산 사이를 연결해 시험합니다. 페이지는 실제 YouTube 모양을 재현한 로컬 fixture이므로 실제 YouTube 전체를 구현한다고 주장하지 않습니다.

레이아웃 설치 검사에서 플레이어와 영상은 1096px에서 1454px로, 진행 막대의 표시 폭과 별도로 저장한 탐색 폭은 1072px에서 1430px로 함께 갱신됐습니다. 실제 마우스로 진행 막대의 25%, 75%, 95% 위치를 눌러 영상 시각을 확인했습니다. 다음 영상, 무관한 DOM 변경 시 알림 비반복, 기능 해제 시 1096/1072px 복원도 확인했습니다.

캡처 설치 검사에서는 실제 문서 식별자가 포함된 영역 선택 메시지를 사용하여 300 × 200 PNG 다운로드와 디버거 연결 해제를 검사합니다. 브라우저 재현이 어려운 대기열·프레임 교체 경계는 Chrome API 전달 시점을 제어한 Node 검사로 별도 확인합니다.

검증 자료는 `docs/verification/full-audit-1.77.4`에 보관합니다.

## 적용과 확인 범위

개발 폴더의 소스와 `dist`를 함께 갱신합니다. 다른 폴더에서 설치했다면 배포 ZIP을 기존 설치 폴더에 반영한 뒤 확장 관리 화면에서 **다시 로드**하고 YouTube 페이지를 새로 고쳐야 합니다. 기존 확장을 삭제할 필요는 없습니다.

개인 Chrome의 확장 관리 페이지는 브라우저 도구에서 열 수 없어 개인 프로필의 확장 재로드는 수행하지 않았습니다. 실제 YouTube에서는 원인과 크기 갱신 방식을 확인했고, 완성된 새 확장의 설치 검증은 별도 임시 프로필에서 수행했습니다. 실제 계정의 Premium 이용 권한, 모든 YouTube 실험 UI, 다른 확장과의 모든 조합은 확인 범위에 포함되지 않습니다.

캡처 문서 검증에 사용한 공개 API: [Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [Chrome DevTools Page protocol](https://chromedevtools.github.io/devtools-protocol/tot/Page/).
