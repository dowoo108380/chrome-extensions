# Browser Toolbox 1.77.0 개선 기록

2026-09-29에 분석한 1.76.0을 기준으로 오류, 취소·자원 관리, 타입 경계, 검증 환경과 배포 구조를 개선했습니다. 과거 분석은 `analysis/2026-09-29`에 남겨 변경 전 결과와 비교할 수 있게 했습니다. 이 문서와 `docs/verification`이 개선 후 상태입니다.

## 확인된 오류와 수정

| 항목 | 이전 문제 | 반영한 수정 |
|---|---|---|
| F-01 자막 수명주기 | 응답 헤더·본문이 멈추면 팝업만 실패하고 실제 작업과 같은 탭 대기열이 남음 | 대기열 포함 45초 기한, 요청별 12초 기한, AbortSignal 전파, 취소 뒤 정리 완료 후 다음 작업 진행 |
| 팝업 종료 | 닫힌 UI가 시작한 자막 요청이 계속 실행될 수 있음 | 소유권을 확인하는 runtime.Port 요청, 연결 해제 시 해당 포트의 작업 취소 |
| 자막 탐색·크기 | 영상 이동·큰 응답·취소 후 늦은 응답 관리 부족 | 탐색 시 취소, 최대 8MiB 스트림 읽기, 캡처 기록 개수·총량 제한, 원래 CC·후킹 복구 |
| F-02 설정 초기화 | 늦은 저장소 읽기가 더 최신 onChanged 값을 UI에서 덮어씀 | 공통 SettingsReadJournal과 읽기 세대 검사 적용 |
| 캡처 자원 | 과도한 페이지 크기를 캡처 API에 바로 전달 | 유효 좌표·크기, 최대 변 32,767 CSS px 및 면적 64Mi CSS px² 검사, 오류 후 디버거 해제 |
| 파일 생성 | 대용량 읽기 중 취소 불가, 큰 임시 버퍼 | 1MiB 단위 CRC 계산, 이벤트 처리 기회 제공, 생성 취소와 페이지 종료 시 중단 |
| 중복 파일명 | 같은 이름이 많으면 앞에서부터 번호를 반복 탐색 | 이름별 다음 번호를 보관하면서 실제 충돌·대소문자·기존 번호 이름 확인 |
| A/B 비용 | 비시청 페이지·숨겨진 탭에서도 URL 확인 타이머 실행 | 표시된 시청 페이지에서만 재예약, 같은 영상으로 복귀하면 A/B 지점 유지 |
| 레이아웃 진단 | 실제 전체 화면에서도 displayMode를 normal로 표시 | Fullscreen API와 사이트의 fullscreen 속성을 반영 |
| 팝업 작은 화면 | 고정 폭 때문에 좁은 화면의 내용 접근 제한 | 가변 최대 크기, 작은 화면 전용 범주 배치와 스크롤 |

자막 취소는 페이지 MAIN 환경과 서비스 워커 사이에 직렬화 가능한 함수·작업 ID를 사용합니다. 함수 주입에 외부 클로저가 따라가지 않는 Chrome 특성을 유지했습니다. MAIN·ISOLATED 파서 연결과 실제 확장 API를 사용하는 검사를 별도로 추가했습니다.

## 코드와 개발 환경

- 전체 제품 TypeScript에 strict 검사를 적용했습니다. 분석 당시 추가로 나온 783개 진단은 현재 타입 검사에서 해소했습니다. 이 숫자는 런타임 버그 수가 아닙니다.
- 전역 `chrome: any`를 제거하고 `@types/chrome`으로 API 인수·결과를 확인합니다. 이벤트 대상, 오류, DOM 노드, 미디어 상태와 외부 자막 데이터의 타입 및 런타임 확인을 보강했습니다. 모든 명시적 any가 제거되었다는 의미는 아닙니다.
- 캡처와 자막 큐·포트 처리를 `background_capture.ts`, `background_captions.ts`로 분리했습니다. 기존 classic service worker/importScripts 방식을 유지합니다.
- 중복된 부분 strict 설정을 삭제했습니다. 과거 결함 재현용 기준선은 당시 선언과 컴파일 조건으로 분리했습니다.
- Node/pnpm 기준, 정확한 TypeScript·Chrome 타입·Python 테스트 의존성, pnpm lockfile을 추가했습니다.
- 중복 빌드 명령을 공통 Node 실행기로 모았습니다. Python·브라우저 탐색, 명시적 경로 인수, 실행기별 시간·성공 여부 기록을 제공합니다.
- CI 정의와 실행 파일 허용 목록 기반 배포 명령을 추가했습니다. ZIP 시간·순서가 고정되고 파일별 해시를 기록합니다. 이번 작업에서 원격 CI 자체를 실행한 것은 아닙니다.

## 테스트 정비

오래된 `player_viewport`, `player_wrapper`, `media_only` 실행기는 제거된 플레이어 확대 방식만 요구하므로 전용 기준선·fixture와 함께 삭제했습니다. 현재 제품을 검증하는 foundation·transition·persistence와 공용 player fixture는 유지했습니다.

width·readiness 테스트에는 현재 레이아웃이 요구하는 네이티브 조작부를 추가했습니다. 정상 너비의 표시를 영화관·전체 화면·좁은 화면에서도 보관하는 기존 1.76.0 계약에 기대값을 맞췄습니다. 크기·복원·원본 영상·스크롤·실제 전체 화면 검증은 유지했습니다.

HTTP 영상 시험 서버는 Range 요청을 처리하도록 수정했습니다. 전환 시험은 무조건 기다리거나 실패를 재시도하는 대신 fixture가 실제 탐색 너비를 갱신했는지 확인한 후 25%·75%·95% 클릭 결과를 검사합니다.

추가 검사는 다음을 다룹니다.

- 자막의 응답 헤더·본문 지연, 명시적 취소, 작업 시작 전 취소, 영상 탐색, 선언·스트림 크기 초과 및 정리
- 늦은 팝업 초기 읽기와 최신 설정 변경의 경쟁
- 자막 포트 발신자·요청 소유권, 연결 종료와 다음 대기 작업
- 실제 설치된 MV3 확장의 자동 콘텐츠 주입, 저장소·메시지, 워커 중단·재시작 후 세션 배속 복원
- 실제 캡처 PNG 다운로드 완료 및 크기 오류 뒤 디버거 연결 해제
- 임시 프로필의 잘못된 사이트 삭제 요청 거부, 선택한 쿠키 삭제와 다른 출처 쿠키 보존
- 실제 MAIN·ISOLATED 환경 사이의 자막 전달과 포트 종료에 따른 네트워크 취소
- 파일 읽기 중 취소, 다운로드 방지, 취소 후 다시 생성, 대량 중복 이름
- A/B 지점 보존, 숨김·비시청 페이지에서 URL 타이머 중단
- 7개 팝업 범주의 좁은 화면 넘침, 키보드 이동·포커스·검색, 강제 색상 모드

## 정리한 자료

프로덕션 실행에 필요하지 않은 파일을 배포 ZIP에서 제외했습니다. 작업 중 만든 타입 변환 스크립트·백업·중간 로그와 폐기된 테스트 출력도 정리합니다. 최초 분석 근거, 현재 회귀 시험, 라이선스 고지와 사용하는 이미지·아이콘은 유지합니다.

README의 긴 과거 릴리스 설명, 전달본에 없는 validation 경로, 중복 검증 명령을 현재 설치·사용·개발·배포 안내로 교체했습니다. 변경 전 분석은 역사적 기록이라는 점을 표시하고 타사 고지를 그대로 보존했습니다.

## 검증 범위와 남은 한계

최종 실행 결과와 환경·해시는 `verification/verification.json`에 기록합니다. 타입 검사, Node 시험 83개, 현재 브라우저 실행기 27개 묶음이 통과했습니다. ZIP 무결성·포함 파일·재현성을 검사하고 압축을 푼 배포본에서도 실제 확장 설치 검사를 실행합니다.

브라우저 검증은 Windows의 임시 Chrome 프로필과 로컬·합성 페이지를 사용합니다. 실제 확장 API 검사는 실행했지만 개인 계정의 YouTube·ChatGPT 화면, 광고·지역별 실험군, 스크린 리더, GPU/VSR 및 장시간 다중 탭 성능은 확인하지 않았습니다. 강제 색상과 확대에 준하는 CSS 뷰포트 검사를 실제 운영체제 접근성 기능 전체의 인증으로 표현하지 않습니다.

사이트 DOM 변경에 대한 지속적인 호환성 점검은 필요합니다. 전체 호스트 권한은 일반 페이지·모든 프레임 미디어 기능에서 사용하므로 제거하지 않았습니다. 기능별 선택적 권한으로 바꾸는 일은 기존 동작과 사용자 흐름을 함께 설계해야 하는 별도 제품 변경입니다.
